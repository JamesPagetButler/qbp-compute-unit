## §3 — API surface: no breaking changes between rc1 and v0.1.0

**Scope:** `emulator/public_api.go` diff from `emulator/v0.1.0-rc1` tag to current HEAD.

**Changes observed:**

1. **New CSR accessor methods** (additive): `SetAMODE`, `AMODE`, `SetBSEL`, `BSEL`,
   `SetPSEL`, `PSEL` — added by M1.1 (PR #52). All new. No existing method signatures
   changed. Consumers pinned to rc1 continue to compile without modification.

2. **Mutex locking added to existing methods** (behaviour-preserving): `QConj64`, `QNorm64`,
   `QMul128`, `QAdd128`, `QRot128`, `QConj128`, `QNorm128`, `QMulHighPrec` now hold
   `g.mu.RLock()` / `g.mu.Lock()`. Protects against data races with concurrent CSR state
   access introduced by M1.1. No API signature change; externally observable behaviour
   is identical for single-threaded callers. Race-detector tests confirm no regressions.

3. **New sentinel errors** (additive): `ErrInvalidAMODE`, `ErrAMODEReserved`, `ErrInvalidBSEL`,
   `ErrInvalidPSEL`. All new. Existing `ErrTierUnsupported` unchanged.

**Verdict:** No breaking changes. The issue gate "No API changes between rc1 and v0.1.0
(or any changes documented as breaking + version-bumped)" is satisfied — all changes are
additive or internally behaviour-preserving.
